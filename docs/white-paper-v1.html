Putting time back into the network

A temporal ordered-network visualisation that shows what learners do, in what order, for how long, and when

Karan Bansal, IIT BombayWhite paper, September 2026Tool: Temporal ONA builder

Abstract

Epistemic and ordered network analysis (ENA and ONA) are widely used to model how coded learning behaviours connect. Their standard plots answer one question well: which behaviours are associated, and in which direction. They answer two others poorly: how much time learners spend in each behaviour, and when in a session each connection happens. Both matter to an instructor watching a self-regulated learning (SRL) activity unfold.

This paper describes a visual design that keeps the ordered network and adds time to every element. Disc area shows the share of time spent in a behaviour. A clock ring around each disc shows when in the session that time was spent. Each arrow doubles as a small timeline that thickens in the minutes a link occurred and is coloured from early to late. A window control rebuilds the network for any part of the session. We specify the data model and computations, release a browser tool that builds the figure from an episode log, and demonstrate it on a synthetic 60-minute programming lab with 30 learners. We close with the design's limits, its relationship to ONA proper, and the ethical conditions for using it with real students.

1Why time goes missing

Self-regulated learning is a process in time. Models such as Zimmerman's (2000) cyclical phases and Winne and Hadwin's (1998) COPES model describe learners who plan, monitor, adjust and evaluate, and who do so repeatedly as a task unfolds. Trace data from learning environments captures exactly this: timestamped episodes of behaviours such as planning, monitoring, debugging, help seeking and evaluation.

Network methods have become a common way to summarise such data. ENA represents associations between codes as an undirected weighted network, and ONA extends it to directed networks so that the order of events is preserved (Shaffer, Collier & Ruis, 2016; Tan, Swiecki, Ruis & Shaffer, 2024). In ONA, a moving stanza window links each line of data, the response, to the preceding lines within the window, the ground. The resulting asymmetric adjacency matrix records how often A was followed by B, separately from how often B was followed by A.

That is a strong model of order. It is a weak model of two other things an instructor cares about.

  • Duration. In standard ONA plots, node size reflects how often a code occurs as a response (Tan et al., 2024). A behaviour that happens rarely but lasts a long time, such as a single twenty-minute debugging episode, looks small. A behaviour logged often in short bursts looks large.
  • Timing. A network accumulated over a whole session cannot tell a Debugging → Help-seeking loop at minute 10 from the same loop at minute 50. Yet the difference matters: the first suggests a poor start, the second a late impasse.

These gaps are not new to the field. Knight, Wise and Chen (2017) argued that learning analytics needs explicitly temporal analysis, and a systematic review of temporally focused SRL analytics found that most studies capture only part of the picture (Saint, Fan, Gašević & Pardo, 2022). Nath, Gašević, Fan and Rajendran (2024) put the problem precisely: temporality in SRL has two perspectives, time as a passage and time as an ordered sequence of events, and a single analytic method is not sufficient to capture both. Their CTAM4SRL method answers this by combining visualisation, network analysis and pattern mining.

This paper takes a complementary route. Rather than placing several methods side by side, it asks whether both facets of time can be carried by a single figure that an instructor can read at a glance. The design keeps ONA's directed network as the backbone, for sequence, and layers passage-of-time information onto every node and edge.

2Design goals

The design was built against five goals, drawn from the instructor's questions and from common failure modes in learning analytics dashboards.

  1. Show order. Keep directed links so that A → B and B → A remain distinct.
  2. Show duration. Encode how much time is spent in each behaviour, not how often it is logged.
  3. Show timing. Make it visible when in the session each behaviour and each link happens, without splitting the figure into disconnected charts.
  4. Stay honest. Every visual quantity must map to a stated number: disc area strictly proportional to time share, one meaning for arrow thickness at a time, and an explicit report of time that was not coded.
  5. Survive print. The figure must work as a static image in a report or exam answer, not only as an interactive dashboard.

3From log to network

3.1 Input

The input is an episode log with one row per coded episode: a learner identifier, a behaviour code, a start time and, optionally, an end time. This is the form most SRL coding schemes and trace-parsing pipelines produce. Times may be minutes from session start, mm:ss, or clock time (hh:mm:ss). The full specification is in Appendix A.

3.2 Preparing episodes

Three preparation steps turn raw rows into clean episodes. Each is a visible, reversible setting because each changes the result.

  • End times. If the log has no end column, an episode is taken to last until the learner's next episode begins. The final episode of each learner then has zero duration, which the coverage report makes visible.
  • Alignment. With clock times, each learner's first episode can be treated as their minute zero. This compares learners by their own session clock. Turning it off keeps a shared class clock, which is the right choice when a lab has a common start and the question is what the class was doing at 10:30.
  • Merging repeats. Loggers often emit the same state repeatedly, for example a "watching video" event every few seconds. Merging back-to-back rows of the same behaviour into one episode removes this noise before links are counted, the same sessionisation step recommended before sequence mining.

3.3 Links

Links follow ONA's logic. For each learner, episodes are sorted by start time. With a link window of w actions, each episode (the response) is linked from each of the w − 1 episodes before it (the ground). A window of two gives immediate transitions only; larger windows capture looser "came soon after" relationships, the trade-off discussed by Siebert-Evenstone et al. (2017). A link from a behaviour to itself is kept as a loop. Every link is stamped with the start time of its response episode, which is what lets it be placed in time.

3.4 Weights and scope

A link can be weighted by count, one per ground–response pair, or by the minutes spent in the response behaviour. Weights and times can be reported per learner (the class mean) or as class totals. The per-learner scope is the default because it keeps numbers interpretable across classes of different sizes.

3.5 Windows and slices

Two time grids structure the figure. The window is the part of the session being shown: the whole session, a fixed frame such as 20–30′, or any custom range. The slice is the resolution of the timing encodings, five minutes by default. For a behaviour b, a window of length T and N learners, the core quantities are:

Minutes per learner: mb = (1/N) Σ overlap(episode, window)
Share of the window: sb = mb / T
Share of slice k: pb,k = Σ overlap(episode, slice k) / (N × slice length)
Link weight: wA→B = (1/N) × number of A→B pairs whose response starts inside the window
Link timing: t̄A→B = weighted mean start time of those responses

4Visual encodings

Each question an instructor might ask is assigned one primary encoding. Where an encoding is redundant with a printed number, the number wins, because people read lengths and positions far more accurately than areas and colour (Cleveland & McGill, 1984).

Two further design decisions are worth stating. First, node colour is categorical and deliberately avoids the violet-to-amber range used for time, so that colour on a disc never reads as colour on a timeline. Second, nodes sit on a fixed circle in the order behaviours first appear in the data. This makes positions stable across frames, so a change in the picture is a change in the data, not in the layout.

5Worked example

5.1 Data

To demonstrate the design we generated a synthetic log for a 60-minute programming lab: 30 learners, 799 episodes and five SRL behaviours (Planning, Monitoring, Debugging, Help seeking and Evaluation). Behaviours were drawn from time-varying probabilities: Planning likely at the start, Debugging peaking around minute 30, Help seeking concentrated around minute 37, and Evaluation rising towards the end. Episode lengths and short uncoded gaps were randomised. The generator is seeded, so the same data appears under Load sample in the tool.

Because the phases were built into the data, the results below are a known-answer test of the encodings, not an empirical finding about learners. The question is whether a reader can recover structure we know is there.

5.2 The whole session

Figure 1 shows the whole session. Three things can be read directly:

  • Where time goes. Debugging dominates at 24.6 minutes per learner, 41% of the session. Planning follows at 11.1 minutes (18%), Evaluation and Monitoring at about 7 minutes each (12%), and Help seeking is small at 2.3 minutes (4%). The coverage line reports 52.5 coded minutes out of 60, so 7.5 minutes per learner are uncoded.
  • What drives the session. The strongest links are the Monitoring ⇄ Debugging pair: 2.9 transitions per learner from Monitoring to Debugging and 2.7 back, both centred around minute 32. This is the classic check-and-fix cycle of programming.
  • When things happen. Planning's ring is darkest in the first ten minutes and Evaluation's in the last ten. The Planning → Debugging and Planning → Monitoring arrows are violet, with average times around minutes 17–19, while the links into and out of Evaluation are orange, centred around minutes 42–46.

5.3 Change across the session

Figure 2 turns the session into small multiples. The story the whole-session view compresses becomes a sequence. In 0–10′, Planning takes half of learners' time (5.0 minutes) and the strongest link is Planning → Monitoring. By 20–30′, Debugging takes 64% of the frame. In 30–40′, Debugging still dominates, but Help seeking rises to 1.0 minute (10%) and the Debugging ⇄ Help-seeking arrows thicken. In 50–60′, Evaluation becomes the largest behaviour (36%), and the strongest link is Evaluation → Monitoring, which suggests learners checking their work against the task.

5.4 What timing adds

Help seeking shows why duration and timing need their own encodings. Across the session it accounts for only 2.3 minutes per learner, and its disc in Figure 1 is the smallest on the page. A frequency- or total-based network would suggest help seeking barely matters. Its clock ring and the 30–40′ frame say otherwise: 1.0 of those 2.3 minutes, about 43%, fall in one ten-minute window, right after the peak of debugging. For an instructor, that is the moment the class is stuck and asking for help, and the moment a short whole-class explanation would reach the most students.

5.5 Two ways to draw time on arrows

The two arrow modes trade clarity against detail (Figure 3). Colour-only arrows reduce each link to its average minute, which reads quickly but hides spread: a link that happens evenly all session and one that happens only at minutes 5 and 55 would both look mid-session. Timeline arrows keep that distribution at the cost of visual noise. We recommend timeline arrows for the whole-session view, where spread matters most, and colour-only arrows for frames, where the frame itself already fixes the time.

6Relation to existing methods

Ordered network analysis. The tool borrows ONA's connection logic, a moving window linking responses to their ground, but it is not an implementation of ONA. ONA normalises each unit's connection vector, applies dimensional reduction, places nodes by optimisation so that the plotted space is interpretable, and supports statistical comparison between groups (Tan et al., 2024). Our figure is a descriptive node-link diagram of mean directed link weights on a fixed circular layout. Its node sizes also differ in meaning: ONA scales nodes by how often a code occurs as a response, while this design scales them by time spent. Researchers who need ONA's statistical comparisons should run ONA itself and can use this design alongside it for communicating timing.

CTAM4SRL. Nath et al. (2024) combine visualisation, network analysis and pattern mining to cover both passage and order. This design aims at the same two facets but inside one figure. The approaches are complementary: CTAM4SRL is an analysis method for researchers; this is a communication layer that a researcher or instructor could apply to its outputs.

Process mining and transition networks. Process maps and transition network analysis also draw behaviours as nodes and transitions as directed edges, with transition probabilities as weights (Rajendran, Munshi, Emara & Biswas, 2018; López-Pernas & Saqr, 2024; Saqr et al., 2024). Their edges usually encode probability rather than count, and like ONA they rarely encode when in the session a transition occurs. The clock ring and timeline arrow could be added to either.

Sequence mining. Sequential and differential sequence mining find frequent multi-step patterns and the patterns that separate groups (Kinnebrew, Loretz & Biswas, 2013). They are better than any network at longer patterns such as Plan → Code → Test → Debug. A network shows pairwise structure; a longer pattern has to be inferred from chains of arrows.

7Reading it with instructors

The figure is intended to support a short, structured reading. We suggest five questions, each tied to one encoding.

  1. Where did the time go? Compare disc sizes and the printed percentages. Is the largest behaviour the one the task intends?
  2. When did each behaviour happen? Read the rings. Did planning happen at the start, or was it skipped? Did evaluation happen before the last five minutes?
  3. What were the main cycles? Find the thickest reciprocal pair. A strong Monitoring ⇄ Debugging pair is productive iteration; a strong Debugging ⇄ Help-seeking pair can signal an impasse.
  4. When did those cycles peak? Read the swell or colour of the main arrows, then step through the frames to confirm.
  5. What is not in the picture? Check the coverage line. A large uncoded share means the conclusions rest on less of the session than the figure suggests.

8Limitations

  • Averages hide learners. A per-learner mean network can be produced by a class in which half the learners debug all session and half never do. The figure should be read alongside distributions or split by group, for example high and low performers, as in differential sequence mining.
  • Parameters change the picture. The link window, slice length, alignment and repeat merging all change counts and timings. Any published figure should state its settings; the tool prints the main ones on the figure and legend.
  • Perception limits. Area and colour are imprecise channels (Cleveland & McGill, 1984), so printed numbers carry the exact values. The violet-to-amber ramp has not been formally tested for colour-vision deficiency; the swell's width provides a second, colour-free cue for timing.
  • Layout and scale. A circular layout guarantees stable positions but not minimal edge crossings. Beyond about eight behaviours the figure becomes crowded; grouping codes is advisable.
  • Descriptive only. There are no significance tests or confidence intervals. Differences between frames or groups should be tested with an appropriate method, such as ONA's group comparisons, before they are claimed.
  • Coding quality. The figure is only as good as the behaviour codes. Human-coded data should report inter-rater reliability, for example Cohen's kappa, before it is visualised.
  • Evidence so far. The demonstration uses synthetic data and has not yet been evaluated with instructors. Whether the encodings are read correctly and improve decisions is an open empirical question.

9Ethics and responsible use

Time-stamped behaviour data is sensitive. It can reveal effort, struggle and disengagement at a fine grain, and a figure makes those patterns easy to share. We recommend the following conditions, in line with checklists for trusted learning analytics such as DELICATE (Drachsler & Greller, 2016).

  • Consent and purpose. Learners must know what is logged, why, who will see it and for how long it is kept. For minors, this means consent from a parent or guardian and assent from the learner in age-appropriate language.
  • Class-level by default. The design shows group means. Individual networks should be shown only for a stated supportive purpose, never used to rank learners, and never shown to peers.
  • Pseudonymised input. The tool needs only a learner identifier, not a name. The published tool runs in the browser and remembers the last pasted log in the browser's local storage for convenience; with real student data, use pseudonymous IDs and clear the data after use.
  • Interpretive humility. Low time in a behaviour is not a verdict on a learner. Learners who work offline or think before they act can look inactive in logs. Figures should prompt questions, not conclusions.

10Future work and conclusion

Four extensions would make the design more useful for research. Group comparison: difference networks that subtract one group's weights from another's, shown with the same timing encodings. Uncertainty: bootstrapped intervals on link weights and time shares, shown as faint envelopes around arrows and discs. ONA-based layout: placing nodes at ONA's optimised positions, so that the timing layer sits on top of a statistically interpretable space. Instructor studies: testing whether instructors read the rings and timeline arrows correctly, and whether doing so changes when and how they intervene.

Network views of learning have been strong on order and weak on time. By encoding duration in disc area, timing in a clock ring, and both the order and the timing of links in the arrows themselves, this design lets one figure answer what learners did, in what order, for how long and when. The synthetic example shows that these encodings recover structure that aggregate networks hide, most clearly for brief but well-timed behaviours such as help seeking. The next step is to test the design on real SRL data and with the instructors it is meant to serve.
